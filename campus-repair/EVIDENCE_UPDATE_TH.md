# เพิ่มข้อมูลผู้แจ้งและบังคับรูปภาพ

เพิ่มชื่อ–นามสกุล รหัสนักศึกษา และรูปภาพที่ต้องแนบในรายการใหม่
รูปช่วยให้ผู้ดูแลตรวจสอบอาการ แต่ยังไม่ใช่การยืนยันตัวตนนักศึกษาอย่างเป็นทางการหรือรับประกันว่าแจ้งจริง
รหัสนักศึกษาเป็นข้อมูลที่ผู้แจ้งกรอก ไม่เชื่อมระบบทะเบียนมหาวิทยาลัย

## ขั้นตอนอัปเดตเว็บเดิม (ต้องเพิ่มตารางก่อนอัปโหลดโค้ด)

ไฟล์ในเครื่องที่ใช้สร้างโปรเจกต์ได้แก้ไขแล้ว หากใช้เครื่องอื่นให้แตก ZIP และติดตั้ง requirements ก่อน
ใน VS Code เปิดโฟลเดอร์ campus-repair ที่มี migrate_evidence.py แล้วรัน:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe migrate_evidence.py
```

โปรแกรมถาม connection string ของ Neon แบบซ่อน ให้ใช้ฐานข้อมูลเดิมที่ Vercel ใช้อยู่
ไม่สร้าง Admin ใหม่ ไม่ลบข้อมูลเดิม เพียงสร้างตารางที่ยังไม่มี
หากใช้ SQLite ในเครื่องให้รัน python -m flask --app app init-db แทน

เมื่อเห็นข้อความ “เพิ่มตารางข้อมูลผู้แจ้งและภาพแล้ว” จึงอัปโหลดโค้ดจาก ZIP:
1. เข้า GitHub → camous-repair → campus-repair
2. อัปโหลด app.py, evidence.py, google_auth.py, requirements.txt, pyproject.toml, schema.sql, schema_postgres.sql
3. เข้า templates แล้วอัปโหลด new_repair.html, detail.html, admin_repairs.html, _table.html, google_account.html
4. เข้า static แล้วอัปโหลด style.css
5. รอ Vercel deploy ล่าสุดสำเร็จ แล้วลองแจ้งซ่อมใหม่

google_auth.py เป็น dependency ของแอปรุ่นปัจจุบัน ต้องอัปโหลดแม้ยังไม่ใช้ Google login
หากไม่ได้ตั้ง GOOGLE_CLIENT_ID/SECRET/REDIRECT_URI ปุ่ม Google จะไม่แสดงและยัง login เดิมได้
ไม่ต้องตั้งค่าบริการเก็บรูปใหม่ ไม่เปลี่ยน SECRET_KEY หรือรหัสผ่าน
ZIP อัปเดตมีเฉพาะไฟล์ที่จำเป็น ส่วน full ZIP มีโปรเจกต์ทั้งหมดสำหรับเก็บสำรอง

## การจัดเก็บและสิทธิ์

- รูป JPG, PNG หรือ WebP สูงสุด 3 MB; ด้านสั้นอย่างน้อย 100 พิกเซล ไม่เกิน 24 ล้านพิกเซล
- ตรวจเนื้อภาพจริง ไม่เชื่อ MIME หรือชื่อไฟล์อย่างเดียว ไม่รับ SVG, GIF หรือภาพเคลื่อนไหว
- ลดด้านยาวไม่เกิน 1280 พิกเซล และจัดเก็บ WebP ไม่เกิน 500 KB โดยไม่เก็บ EXIF/พิกัด GPS
- เก็บภาพใน repair_evidence: SQLite BLOB หรือ PostgreSQL BYTEA ใน Neon เดิม ไม่ใช้ดิสก์ Vercel
- เจ้าของรายการและ Admin เท่านั้นอ่านรูปได้ แม้เปลี่ยน URL เปิดภาพโดยตรง
- ภาพไม่อยู่ใน static, ไม่ใช้ URL สาธารณะ และส่ง Cache-Control: no-store
- รายการเก่าที่ไม่มีข้อมูลใหม่ยังเปิดดูได้ พร้อมข้อความว่าไม่มีหลักฐานจากระบบรุ่นก่อน
- สถานะ/ประวัติ/ภาพสร้างใน transaction เดียว ถ้าขั้นตอนหนึ่งผิดพลาดจะ rollback
- Admin ค้นหารหัสนักศึกษาและชื่อที่กรอกในแบบฟอร์มได้

ภาพในฐานข้อมูลจะกินพื้นที่แผนฟรี เช่น 1,000 ภาพที่ขนาดสูงสุดใช้ประมาณ 500 MB ก่อนคิดข้อมูลอื่น
ควรติดตามโควตา Neon และสำรองข้อมูลเป็นส่วนตัว เมื่อใช้งานจำนวนมากจึงค่อยย้ายไป object storage
ชื่อ รหัสนักศึกษา และรูปเป็นข้อมูลส่วนตัว ไม่ต้องถ่ายบัตรนักศึกษาเพื่อส่งเข้าระบบ

## ลองหลัง deploy

1. User เปิดแจ้งซ่อม: ต้องมีชื่อ–นามสกุล รหัสนักศึกษา และช่องรูปที่บังคับ
2. ไม่เลือกรูป/กรอกรหัสผิด → ส่งไม่ผ่าน แม้ปิด validation ของ browser ก็ถูกตรวจที่ server
3. ส่งข้อมูลครบและรูปจริง → เห็นข้อมูลผู้แจ้งพร้อมภาพในหน้ารายละเอียด
4. Admin เปิดรายการ → เห็นภาพ และค้นหาด้วยรหัสนักศึกษาได้
5. User อีกคนเปิด /repairs/เลขรายการ/photo → ได้ 404
6. เปิดรายการเก่า → ดูได้ตามเดิม แม้ไม่มีภาพ

ยังไม่ได้ migrate ฐานข้อมูลของผู้ใช้หรือ deploy รุ่นนี้; ต้องทำขั้นตอนข้างต้นด้วย connection string ของคุณ
